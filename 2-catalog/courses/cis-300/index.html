CIS 300 - Data and Program Structures

Course Description

A study of common data and program structures together with associated algorithms. Topics include interfaces, design patterns, and common data structures (such as arrays, stacks, queues, lists, trees, graphs, hash tables), as well as common algorithms that utilize these structures. Students will gain experience with both use and implementation of these structures and algorithms using a modern programming language. Students will also learn the various tradeoffs involving performance and software maintainability in data structure choice.

Credit Hours

3 credits

Course Overview

This course examines the fundamental data structures, algorithms, and software design principles used in modern computing. Students will learn to analyze, implement, and apply common data structures such as arrays, stacks, queues, lists, trees, graphs, hash tables and more, along with the algorithms that operate on them. Through hands-on programming experiences, students will explore interfaces, abstraction, and design patterns while developing solutions to computational problems and data structures. Emphasis is placed on evaluating algorithm efficiency, understanding performance tradeoffs, and selecting appropriate data structures to create efficient and maintainable software.

Course Goals and Learning Outcomes

  1. Write programs which implement and use abstract and reference-type data structures, including, but not limited to:

    • Strings and string parsing (and related structures like string builders)
    • Lists and arrays
    • Linked lists
    • Stacks
    • Queues and priority queues
    • Trees (including, but not limited to binary search trees, AVL trees, and tries)
    • Hash tables
    • Dictionaries
    • Heaps
    • Graphs

  2. Select and use appropriate data structures to solve real-world problems.

  3. Understand and explain how the performance of a program may change based on the data structure chosen.

  4. Implement and apply algorithms for searching, sorting, and manipulating a data structure.

  5. Understand and use fundamental algorithms for data structures listed in SLO #1, including, but not limited to:

    • Standard sorting/search algorithms (i.e., insertion, merge, quick sort, etc.)
    • Advanced sorting/searching algorithms (e.g., Dijkstra’s, greedy, bucket/radix, etc.)
    • Tree algorithms
    • Graph algorithms
    • Recursive and iterative algorithms

  6. Analyze performance differences and complexity between various algorithms and data structures as outlined in SLO #1.

  7. Utilize advanced object-oriented concepts, such as generics, interfaces, indexers, and enumerators, to implement or partially implement data structures.

Course Prerequisites

The prerequisites for this course are CIS 200 and either DISCRETE MATH 4 or MATH 220. A grade of a C or better is required for each prerequisite.

Required Textbooks and Equipment

Textbook will be freely available at textbooks.cs.ksu.edu.

Grading

Grading Modality: Graded (A, B, C, D, F, I)

Course Schedule

Week Topics
1 Course Introduction, Development Environment, Source Control, File I/O Fundamentals
2 Strings, String Processing, Stack Applications
3 Stack Implementation, Queue Fundamentals, Queue Applications
4 Queue Implementations, Linked Lists, Dynamic Data Structures
5 Algorithm Analysis and Problem Solving with Lists
6 Exam 1, Dictionaries and Associative Data Structures
7 Dictionary Implementations, Arrays vs. Linked Structures, Introduction to Trees
8 Binary Search Trees, Tree Operations, Tree Traversals, Balanced Trees
9 Tries and Advanced Tree Structures
10 Trie Applications, Priority Queues, Huffman Coding
11 Exam 2, Hash Tables and Rehashing
12 Hashing Techniques, Equality, Memoization, Enumerators
13 Graph Fundamentals and Shortest Path Algorithms
14 Graph Implementations, Graph Algorithms, Exam 3, Elementary Sorting Algorithms
15 Advanced Sorting Algorithms, Merge Sort, Hybrid Sorting, Course Review

Assignments

Student performance is assessed through review quizzes, lab assignments, homework projects, and exams. Review quizzes help prepare students for upcoming labs and may be taken twice, with the higher score recorded. Weekly lab assignments provide hands-on programming experience and must be completed during the lab period for credit. Large programming homework assignments are completed throughout the semester, with the final assignment serving as a comprehensive project. Students will also complete coding-based exams. Together, these assessments emphasize preparation, participation, programming practice, and mastery of data structures and algorithms.

Proposed Changes

  • Spatial indexing (quadtrees, R-trees, geohashing). thread-data-structures.md (Data Structures & Representation spiral) describes CIS 300 carrying an applied geospatial-representation touchpoint alongside the graph sub-spiral, riding on the trees/hashing content already in this course. Not currently in the schedule above — proposed as an addition to the Week 13-14 graph/hashing span rather than a displacement of existing content. Needs a course-designer/faculty decision on exact placement and whether it fits without growing the course’s already-flagged density.
  • Client/server vehicle not reflected in this page. cs.md confirms (2026-07-13) this course’s practice vehicle is a server layer in a client/server web architecture, deliberately paired with CIS 320 as the client side — but that’s a program-specific implementation detail of how the data structures are exercised, not itself a catalog-facing learning outcome, so it’s deliberately not spelled out in the description/schedule above the way a generic syllabus wouldn’t name its specific project scaffolding. Noting it here so the omission reads as intentional rather than a stale/dropped design decision.
  • Reorder divide-and-conquer/sorting ahead of the graph unit. thread-algorithmic.md (Algorithmic Thinking & Complexity spiral) describes a Step 2 → Step 3 escalation — design-pattern strategies (divide and conquer via mergesort, greedy algorithms, an introduction to dynamic programming) generalizing into Step 3’s harder-structure optimization (shortest path/MST, graph algorithms). The real schedule above teaches it backwards: Week 15 (Advanced Sorting, Merge Sort) comes after Weeks 13-14’s graph/shortest-path work, not before. Proposed: move the sorting-algorithms content (currently Week 15) to precede Week 13’s graph unit, so mergesort’s divide-and-conquer framing is available before shortest-path/MST is taught as a harder instance of the same design-pattern reasoning. Also worth naming greedy algorithms and dynamic programming/memoization explicitly wherever they land, since the current schedule only names “memoization” (Week 12, paired with hashing) without a clear DP framing. Needs a course-designer/faculty decision — this is a real reordering of confirmed content, not just an addition.
